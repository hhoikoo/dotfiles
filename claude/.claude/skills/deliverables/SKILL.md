# Deliverables

Apply this to anything written for people other than the user in this chat: decks, articles, docs, PR bodies, Slack and email.

## Content

Show what a thing does. Use the names and words the reader already knows. Describe the current state, and keep history for changelogs, decision records and commit messages. Documents for colleagues give the background a reader outside the project lacks and define each term of art at first use.

## Order and titles

Put the problem before the solution, the standard case before the variant, and optional material last. Titles state the point in plain sentence case. Follow the user's latest style choice.

## Articles

- Give the article one purpose from title to conclusion.
- Let each section state its purpose and end on a verdict.
- Cut a true fact that has no point.
- Open with the finding and give evidence in order of importance.
- Use literal wording.

## Visuals and outgoing text

- Label each part of raw output, and show fewer items.
- Label values and features directly on the chart as plain text, and put the headline metric in the title or caption.
- Write a standalone document for colleagues as a local HTML file in white and monochrome. PR bodies, commit text and messages stay plain text.
- Make outgoing text factual and diplomatic.
- Make paste-ready output a plain list of lines.
